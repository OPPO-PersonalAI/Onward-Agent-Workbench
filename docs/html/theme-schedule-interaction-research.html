02 / EVIDENCE

从成熟产品提炼交互模型

下表区分官方可验证行为与本项目的设计推导。后文的重叠、临时覆盖规则属于 Onward 的建议方案，不代表 Apple 未公开的内部规则。

产品 / 来源已验证行为对 Onward 的启发
iPhone · Dark ModeiOS 26 指南：显示与亮度 → 自动 → 选项 → 日落到日出 / 自定时段。该入口调度的是浅色 / 深色外观。每天两态切换可以非常简洁；这不能证明 Apple 系统外观已有任意多主题调度。
Apple · FocusiPhone 支持时间、地点、App 计划。macOS 26 指南明确列出开始时间、结束时间、重复星期、编辑计划及停用开关。最接近本需求：一条可理解的时间段配一个启用状态。把「何时」与「用哪个主题」放在同一条规则里。
Focus · temporary activationiPhone 提供一小时、离开此位置前等临时启用方式；Mac 还支持日历事件结束前。文档没有由此定义主题恢复规则。临时选择要有可理解的终点。「到下一个时段边界」是本项目需要主动确定的契约。
macOS · Auto appearancemacOS 26 指南说明：Auto 按 Night Shift 计划变化，并等待 Mac 空闲至少一分钟后切换。切换时机本身也是交互品质。Onward 要保护正在进行的工作；是否延迟至空闲需另行决策，因为它会改变准点预期。
WWDC22 · Focus filtersApple 明确把 App 主题、布局列为 Focus filter 的应用场景；Calendar 示例展示了筛选状态与切换入口。自动情境需要解释自己改变了什么，并提供控制入口。直接接入系统 Focus 则是另一个平台相关功能。
VS Code监听系统外观；可分别指定浅色、深色与高对比度主题。主题选择器支持键盘浏览预览。切换条件与主题内容分别配置；沿用用户熟悉的主题预览。
JetBrains IDEsSync with OS 可配置映射的界面主题与编辑器配色；系统日夜切换可带动 IDE。保留简单的「跟随系统」入口；应用自己的时间表是独立选择。
PowerToys Light Switch支持固定时间、日落日出、跟随 Night Light、关闭计划，以及手动切换快捷键。固定时间可直接满足核心需求。日落日出引入地点依赖，应作为独立的后续决策。
Auto Dark Mode官方功能列表包含延后下一次切换，以及游戏期间避免切换。好的自动化要容纳临时例外；临时主题需要容易操作、状态可见。

Apple HIG · 尊重系统

Dark Mode 指南建议避免额外的 App 外观模式设置。Onward 已有命名主题选择，且本次需求明确要求定时，因此这里的有意适配是：新用户仍默认跟随系统，定时由用户主动选择。

Dark Mode / Settings

Apple HIG · 按需呈现

选择器适配地区格式、支持键盘输入，并靠近被编辑值；展开控件可收起高级选项；无障碍指导要求状态表达不能只依赖颜色。

落在本方案中：就地时间字段、专注的规则编辑区、文字状态，以及辅助概览而非强制拖拽。

Pickers / Disclosure / Accessibility
值得借鉴的真实信任问题

PowerToys 0.95.0 的用户报告描述：升级后自动切换被启用，覆盖了手动选择的主题。这是历史个案，不能当作当前版本结论。对 Onward 的启发是：定时应由用户主动启用，当前主题的来源应始终可解释。

05 / CONTRACT

让自动切换可信的行为规则

用户于 2026-10-19 回复 go，同意按推荐组合推进：重复时间段、显式空档主题、临时选择保持到下一时段边界。下表保留原方案依据；实现契约记录于 docs/themes.md。

场景建议行为原因 / 代价
未命中时间段使用显式指定的「其他时间」主题；首次可预填当前生效主题，并展示出来。确定、简单。另一选项是其他时间跟随系统，但会多一个动态切换来源。
时间段重叠保存或启用时，行内指出与哪条规则、哪些日期、哪个时段冲突；允许首尾相接。避免隐藏优先级。代价是用户需要调整时间；已关闭规则可以保留。
跨夜与星期星期按开始日计算：周一至周五 19:00–07:00 包含周五晚到周六早。显示「次日」；包含开始、不包含结束。把一整晚理解为同一次安排。开始等于结束时报错，避免暗含「全天」语义。
定时期间手动选主题明确的「临时切换」保持到下一个已启用时段的开始或结束，以较早者为准，并显示具体日期时间。「恢复定时」立即取消覆盖；「手动」明确永久退出。保留安排，也避免立刻跳回。没有启用规则时显示其他时间主题，并引导添加规则或改为手动。
临时覆盖期间修改时间表保存时间表变更时结束临时覆盖，按新安排重新计算；适用时在保存按钮旁预告这一效果。避免恢复时间与新规则不一致。另一个选择是固定原恢复时间，但需更多状态解释。
重启 / 唤醒 / 关闭所有窗口启动、唤醒时使用此刻对应的主题，不补播错过的切换。临时覆盖建议带明确到期时间跨应用重启保留，到期自动失效。避免错误首屏与重启后意外变色。需要评审持久化契约，并统一原生窗口、preload 与 Renderer 的结果。
时区 / 夏令时规则跟随设备本地钟表时间；时钟、时区改变后重新判断。夏令时跳过或重复某小时，按当前本地时间判断，不逐条补触发。更贴合出差时的日常作息。夏令时中的下一次切换及临时覆盖到期，需在实现前列出明确验收用例。
主题编辑 / 保存失败现有全局调色草稿保持预览；保存或取消后按当下时间重新解析。新增时段的选主题采用局部预览。保存失败保留草稿及上次成功保存的时间表。定时事件不能打断调色，也不能让保存失败看起来已经生效。
主题不可用 / 关闭定时引用主题不可用时用其他时间主题，并标注对应规则待修复；切换模式保留已配置时间段；全部规则关闭时使用其他时间主题。可恢复且原因可见；其他时间主题自身损坏时，还需要明确内置兜底。

首版候选范围：固定本地时间 + 按星期重复 + 任意已保存主题。日落日出、地点 / 应用触发、节假日例外、跨设备同步，各自需要独立产品契约，可后续评估。

06 / DELIVERY

接入现有主题体系，并验证真实体验

集成方向 · 待评审

现有解析器同时服务原生窗口、preload 首屏与 React。建议让小型纯函数的时间段判定接入这条链路，由一个生命周期管理入口处理时刻边界、唤醒与时钟变化；Renderer 负责输入和配色应用。

主进程统一管理是候选方向，可避免依赖后台 Renderer 定时器。交互契约确认后，再评审 IPC、覆盖到期持久化与计时语义；如此小的判定无需单独增加 Worker。

单元层 · 确定性逻辑

  • 同日 / 跨夜、精确边界、跨周、周五晚到周六、无启用日期。
  • 跨午夜重叠、首尾相接、起止相等、主题缺失、非法存储值。
  • 空档主题、临时覆盖到期、模式变更、旧手动 / 系统设置迁移且不自动开启定时。
  • 注入时钟与时区：日期边界、时钟前拨 / 后拨、夏令时缺失 / 重复小时与下次切换计算。

自动化层 · 真实用户体验

  • 常见路径：增改启停删除、保存 / 取消 / Escape、编辑不提前全局变色、当前 / 下次原因、临时切换与恢复。
  • 高频路径：反复改模式 / 规则、跨时段边界，正确性内部重复五次；保留 Prompt 输入、焦点、终端与编辑器模型。
  • 压力路径：六个 Task 输出中切主题、反复唤醒、边界时刻修改规则、保存失败重试、快速修改后的旧结果。
  • 300–600px 中英布局、键盘与读屏标签、真实重启和首屏一致性；macOS / Windows / Linux 原生验收。

这里是验收计划，不是已经完成的功能测试。现有已加载主题切换测试有已批准的 200ms 预算；新的延迟指标与预算需另行确认。本轮对 Windows / Linux 做设计层兼容性审视，未原生运行。

07 / DECISIONS

实现前，先确认三个产品选择

建议

多个时间段

采用时间段列表，含星期重复、跨午夜；重叠时给出可操作的行内提示。

另一选择：只做简单的日夜两套。

建议

明确的其他时间主题

空档使用指定主题，首次预填当前主题。

另一选择：空档跟随系统；更灵活，也多一个自动切换来源。

建议

手动选择可临时生效

保留时间表，到下一时段边界恢复，明确显示时间；手动模式是单独的永久选择。

另一选择：选主题立即退出定时，延续目前卡片退出系统模式的行为。

评价：时间段列表是现有主题模型的自然扩展。主要潜在设计债是状态归属不清或隐藏优先级，因此应先确认行为契约再实现。后续可用性验证重点：用户能否无需解释就预测周五跨夜行为，以及临时主题何时结束。
